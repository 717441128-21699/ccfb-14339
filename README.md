# RTS 锁步房间服务模拟

走帧锁步(deterministic lockstep)对战的房间服务原型,全部使用 TypeScript,
房间服务运行在浏览器 **Web Worker** 中,单位与地图由种子确定性生成。

## 解决的问题

| 痛点 | 方案 |
| --- | --- |
| 输入延迟写死 6 帧,好网黏手 | 按各玩家到房间的 RTT/抖动 EWMA 动态计算延迟(2~18 帧),好网自动缩短 |
| 网差一卡全场卡 | 房间收齐每帧指令再广播;等待窗口内先等,超时按规则补空指令,对局不停 |
| 延迟调整时画面跳 | 爬坡每帧最多 ±1 帧、全程 ≤ 40 帧(2s);只改新指令的目标帧,已排队指令不动 |
| 掉线玩家被推平 | 掉线即由 ContinuityAI 接管:先做完掉线前的命令,再自动索敌/聚拢,不发呆 |
| 外挂/脚本 | 房间逐条校验归属(只能操作自己的存活单位)、seq/帧窗口、人手频率窗口与微操检测 |
| 状态不一致难以发现 | 纯 Q8 定点整数模拟,客户端周期性上报世界哈希,房间权威比对 |

## 目录

```
src/core/      定点数、地图、确定性世界、掉线 AI(与传输无关的纯逻辑)
src/net/       房间服务、校验器、延迟控制器、虚拟链路、虚拟客户端、测试线束
src/worker/    Worker 内运行的房间服务入口
src/ui/        主线程 Canvas 渲染与控制面板
tests/         Vitest:延迟调整、安全、AI 接管、房间语义、确定性、性能
```

## 命令

```bash
npm install
npm test          # 全量测试(含 2000 单位性能基准)
npm run bench     # 只跑性能基准
npm run dev       # 浏览器演示:http://localhost:5173
npm run build     # 类型检查 + 构建
```

浏览器演示面板可实时调整玩家 1 的单向延迟/抖动/丢包、一键切换
好网/差网、复现 RTT 50→300ms 场景、强制掉线观察 AI 接管、注入脚本爆发。

## 关键设计

### 帧调度(`src/net/room.ts`)

1. 每 50ms 一个逻辑帧,固定 20Hz 关帧广播,不随网络抖动改变帧率;
   房间为每个玩家缓存按 `targetFrame` 索引的指令。
2. **单帧无命令是合法锁步输入,不阻塞关帧**。只有玩家超过 `stallFrames`
   (默认 12 帧)没有任何上行消息(命令/ack/pong)才判定卡顿,该槽位补空
   指令并广播 `backfill` 事件 —— 正常网络下补空次数为 0。
3. 超过 `disconnectFrames`(默认 30 帧)无消息判定掉线,AI 以该玩家身份
   通过同一条指令通道补帧(校验器对内部 AI 豁免频率限制,归属校验不豁免)。
4. `FrameBundle.slots` 按 `playerId` 升序、人数恒定,保证各客户端输入
   序列一致;客户端用帧缓冲按序消费,乱序到达也绝不跳帧。

### 动态输入延迟(`src/net/delay.ts`)

```
需要时延 = RTT_EWMA / 2 + 2 * 抖动_EWMA + 40ms 调度余量
目标延迟 = clamp(ceil(需要时延 / 50ms) + 1, 2, 18) 帧
```

当前延迟按**固定节拍**向目标爬坡,每 2~3 个关闭帧变化 1 帧,任何幅度的
调整都在 40 帧(2 秒)内完成;节拍不随 EWMA 的小幅抖动重置,避免爬坡
被反复中断。RTT 由房间每 500ms 的 ping/pong 测量(在途探测未返回时不发
新探测,控制面允许丢包、下轮自愈)。延迟变化只作用于之后产生的新指令,
已排队指令的目标帧不改写,因此画面不跳。

### 确定性(`src/core/fixed.ts`, `world.ts`)

- 坐标与移动全部 Q8 定点整数,除法显式四舍五入,无浮点三角函数;
- PRNG 为 mulberry32,各子系统持独立状态、按固定顺序步进;
- 单位按 id 顺序更新,空间分桶用扁平 Int32 链表,每帧零对象分配;
- 每 30 帧客户端上报 FNV 哈希,与房间权威世界比对。

### 安全(`src/net/validator.ts`)

- 归属:单位必须存在、存活且属于指令发起者;
- 时序:seq 严格递增,目标帧不得过期或过度超前;
- 频度:60 帧滑动窗口内动作批 > 24 且连续两个窗口超标 → 脚本标记;
  单单位 60 帧内被下令 > 30 次 → 微操机器人标记。标记只告警不断局,处置策略留给上层。

## 性能

2000 单位、128×128 地图、24 个障碍:热身后 `world.step` 平均与 p95 耗时
由 `tests/bench.sim.test.ts` 实测并断言(平均 < 8ms,p95 < 10ms)。
